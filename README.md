# Драфт — сценарный редактор

Русскоязычный аналог Final Draft для сценарных групп: строгий мировой формат страницы (Courier 12, отступы элементов, 1 страница ≈ 1 минута), подсказки имён персонажей и объектов, хронометраж, процент объектов и павильона, проверка производственных параметров студии, комментарии продюсера, драфты, библия персонажей и экспорт, который без правок читает FilmToolz и Final Draft.

Прототип работает целиком в браузере и не требует сервера: данные хранятся в IndexedDB. Следующий этап — облачная версия с общей базой, правами и резервными копиями (см. `docs/`).

## Состав

| Путь | Что это |
|---|---|
| `app/index.html` | разметка интерфейса |
| `app/styles.css` | стили, светлая и тёмная тема, геометрия страницы |
| `app/core.js` | «ядро» без DOM: формат и пагинация, разбор заголовков, анализ серии, правила студии, импорт (FDX, Word, PDF, текст), экспорт (FDX, Word для FilmToolz, Fountain), история и откат. Работает и в Node |
| `app/app.js` | интерфейс: редактор, меню, панели, автодополнение, комментарии, драфты, история (автоснимки и версии), корзина, настройки |
| `app/fonts.js` | встроенный шрифт FreeMono (латиница + кириллица) для PDF и для машин без Courier New |
| `build.py` | собирает `app/_test.html` для тестов и один автономный файл `dist/Драфт.html` |
| `tests/` | модульные тесты ядра (`test_core.js`, `test_lock.js`, `test_docx.js`, `test_pdf.js`, `test_lines.js`…) и сценарии Playwright (`test1.js` … `test14.js`, `test_*_ui.js`) |
| `docs/` | ссылки на спецификацию и документ о сохранности |

## Запуск

```bash
npm install            # библиотеки для тестов; сам редактор ничего не требует
npm run build          # dist/Драфт.html — один файл, открывается двойным щелчком
npm test               # тесты ядра
npm run test:ui        # сборка + сценарии в безголовом Chromium
```

Во время работы редактор подгружает из cdnjs четыре библиотеки: jszip (Word), jspdf (PDF-экспорт), pdf.js (PDF-импорт) и sql.js 1.10.3 (WebAssembly-сборка SQLite: файлы КИТ Сценариста и Story Architect). Без интернета всё остальное работает.

## Образцы сценариев

Реальные сценарии студии (`samples/`) в репозиторий не кладутся: репозиторий открытый. Тесты импорта (`test6`, `test7`, `test9`, `test_docx`, `test_lines`) ждут файлы `samples/treshka.docx`, `samples/ies51.pdf` и распакованный `samples/x/word/` локально.

## Окно

Как в Final Draft: строка меню (Файл, Правка, Вид, Формат, Документ, Производство, Справка), панель инструментов, страница, строка состояния. На панели инструментов только то, что нужно каждый день: тип элемента, отменить/повторить, комментарий, кнопка **PDF** (**Ctrl+P**) и переключатели панелей. Меню Файл построено как в Final Draft: Новая серия, Новый сезон, «Открыть…» (один диалог для файла проекта `.json` и для сценария Word, PDF, .fdx, Fountain, КИТ, Story Architect), «Сохранить» (**Ctrl+S**, на этом компьютере), «Сохранить как файл проекта…», «Сохранить версию…» (**Ctrl+Shift+S**), «История…», «Корзина…», подменю «Экспорт ▸» (PDF, Final Draft .fdx, Word для FilmToolz, Fountain, библия персонажей; «Разбивка в Excel» — в режиме «Продюсер»), «Параметры страницы…», «Настройки…». Файл, брошенный мышью в любое место окна, загружается так же, как через «Открыть…». Вкладки навигатора (Серии, Сцены) и панели производства (Время, Параметры, Замечания, Персонажи, Объекты, Разбивка) открываются через Вид → «Навигатор» / «Производство» и щелчком по вкладке; отдельных пунктов меню для них нет. Пункты, которых нет в режиме «Сценарист», скрыты вместе с опустевшими разделителями; меню, в котором ничего не осталось (Производство у сценариста), не показывается. Настройки разнесены по трём коротким окнам: «Настройки…» (личные: имя, режим, тема, шрифт на экране — Файл), «Титульный лист…» (название проекта, автор, контакты, подпись драфта, обладатель коммерческой тайны — Документ, как Title Page в Final Draft) и «Параметры студии…» (правила, линии с долями, нормы выработки — Производство, режим «Продюсер»). «Параметры страницы…» (Файл, как Page Setup) — шаблон листа (Letter / A4 с отступами Final Draft / A4 «американка») и минут на страницу. У каждого окна одно место в меню. Меню Документ: Серия… (сезон, номер, название, удаление серии), Проект… (сколько серий, персонажей и объектов; удаление проекта), Титульный лист… (название проекта и автор — только здесь), Сводка сезона… (режим «Продюсер»). Кнопки «Удалить серию» и «Удалить проект» видны в обоих режимах; у сценариста они открывают окно «Нужен режим „Продюсер“». Меню Вид: Навигатор, Производство, Режим фокуса (только страница; все три — с галочкой, пока включены), Разметка разбивки, масштаб, тема. Меню Правка: Отменить, Повторить, Вырезать, Копировать, Вставить, Выделить всё, Комментарий к выделенному…, Найти и заменить…, Заменить…, Перейти к странице или сцене…; то же по правой кнопке на странице (там «Комментарий…» и подменю «Элемент»). Меню Формат: тип элемента, Жирный, Курсив, Подчёркнутый, Двойной диалог, Разрыв страницы перед элементом. Строка состояния показывает режим и имя («Режим: Продюсер · Иван»; пока имя в «Настройках» не заполнено — только «Режим: Сценарист», а под комментариями, локами и драфтами такой участник подписан «Без имени»); если вкладка устарела из-за правки в другой, она говорит «Только чтение», а выбор элемента и кнопки отменить/повторить с панели инструментов уходят.

## Режимы

Два режима вместо ролей, переключатель в Файл → «Настройки…» (`S.me.role`: `writer` или `producer`, хранится в этом браузере; старые значения «редактор» и «читатель» при загрузке становятся «продюсер» и «сценарист»). Текст правят в обоих.

- **Сценарист** — текст, формат, комментарии, история, экспорт: короткие меню, как в Final Draft. Меню Производство, вкладка «Разбивка» и «Сводка сезона» не показываются.
- **Продюсер** — то же и производство: меню «Производство» и панель «Производство» целиком, лок номеров и страниц, драфты, сайды, разбивка (с Excel), журнал действий, «Параметры студии», удаление серий и проектов (сценаристу вместо этого показывается окно «Нужен режим „Продюсер“»).

Экземпляр для чтения (актёру, каналу) — PDF с галочкой «Водяной знак с именем получателя» в окне PDF: она включена, пока заполнено «Для кого», и имя получателя печатается по диагонали на каждой странице и в колонтитуле. Отдельной роли читателя и водяного знака на экране нет. В строке состояния виден режим и имя; журнал действий, комментарии и журнал сайдов записывают режим вместе с именем.

## Формат

За образец взят Final Draft: Letter, поля 1" сверху/снизу/справа и 1,5" слева, Courier 12, 54 строки на странице. Отступы элементов от края листа: сцена и описание 1,5", персонаж 3,5", ремарка 3,0", реплика 2,5", переход 5,5"–7,1" (вправо). Диалог на разрыве страницы получает (ДАЛЬШЕ) и (ПРОД.) — в PDF и прямо на экране: под последней строкой реплики на странице «(ДАЛЬШЕ)», после линии «стр. N» имя с пометкой («ИВАН (ЗК) (ПРОД.)»), на отступе персонажа. Это не текст: их нельзя выделить или стереть, они пересчитываются вместе с вёрсткой. Если страница рвёт саму реплику, в ней открывается промежуток в четыре строки (на экране текст идёт сплошь, поэтому граница стоит после той строки, где её ставит вёрстка, а не точно у точки, как на бумаге). Есть вариант A4 на 58 строк (Файл → «Параметры страницы…»).

### Двойной диалог и кадр

- **Двойной диалог** (Формат → «Двойной диалог», **Ctrl+D**), как Format → Dual Dialogue в Final Draft: две реплики, которые звучат одновременно, стоят рядом. Поставьте курсор во вторую реплику (или в первую — тогда в пару встанет следующая) и выберите команду; повтор на реплике из пары ставит их снова одну за другой. Пометка хранится на втором персонаже (`block.dual`) и путешествует с текстом: Ctrl+Z, драфты, история, файл проекта. Включение и снятие — правка, она получает звёздочку текущего драфта.
- Колонки — половины колонки описания: на Letter реплика с 1,5" и 4,5" шириной 2,7", ремарка на 0,5", персонаж на 1,0" от края своей колонки (персонажи на 2,5" и 5,5"); на «американке» — так же от её полей. Так же на экране, в пагинации и в PDF. Пара не разрывается: если не помещается, переходит на следующую страницу целиком (заголовок сцены — вместе с ней), без (ДАЛЬШЕ)/(ПРОД.). Высота пары — по длинной колонке, поэтому и страницы, и хронометраж считают её один раз. Пара выше страницы (на практике не бывает) печатается одна реплика за другой. Третья реплика к паре не добавляется.
- .fdx: пара пишется и читается как `<Paragraph><DualDialogue>…</DualDialogue></Paragraph>`; Fountain: `^` после имени второго персонажа (`@МАША ^`). Word для FilmToolz: реплики пары идут одна за другой (FilmToolz колонки не нужны, текст и персонажи сцены те же).
- **Кадр** (Shot Final Draft, **Ctrl+7**, Формат → «Кадр», список элементов): «КРУПНО — ЛИЦО ИВАНА». Колонка описания 1,5", заглавные, одна пустая строка перед; как заголовок, не остаётся один внизу страницы. Enter после кадра — описание. Ctrl+1…6 — как раньше. .fdx: `Type="Shot"` в обе стороны; Word: стиль «Shot»/«Кадр» при загрузке, отступ описания и заглавные при выгрузке; Fountain: отдельная строка заглавными между пустыми строками (описание заглавными выгружается с `!`, чтобы не стать кадром).

### Стили текста, разрыв страницы, (ПРОД.), цвет сцены, правка

- **Жирный, курсив, подчёркнутый** (Формат → «Жирный» / «Курсив» / «Подчёркнутый», **Ctrl+B / Ctrl+I / Ctrl+U**), как Format → Style в Final Draft: применяются к выделенному (и через несколько элементов) или к слову под курсором; если всё выделенное уже со стилем, он снимается, иначе ставится. Текст элемента (`block.x`) всегда чистый; стили лежат рядом с ним (`block.st`: отрезки `[от, до, биты]` по буквам текста, 1 жирный, 2 курсив, 4 подчёркнутый) и путешествуют с текстом везде: Ctrl+Z, драфты, история, файл проекта, звёздочки правок, вырезать/копировать/вставить внутри редактора (вставка из другой программы — чистый текст). Поэтому звёздочка или подчёркивание, набранные с клавиатуры, пришедшие из .fdx, Word, PDF, текста или из старого файла проекта, — просто знаки: «2*3*4» так и остаётся на экране, в PDF и во всех выгрузках; стиль появляется только от Ctrl+B/I/U или из оформленного прогона загруженного файла. Заголовки сцен, персонажи, переходы и кадры всегда без стилей: Ctrl+B на них ничего не делает (всплывающее сообщение), а смена типа элемента на такой (Ctrl+1/3/6/7, список элементов, правая кнопка) снимает стили, так что имя остаётся одним именем. Курсор, комментарии, пометки разбивки и поиск считают видимые буквы. В PDF жирный печатается жирным Courier, подчёркивание — линией, курсив — наклоном того же шрифта (отдельного курсивного шрифта в файле нет); стиль не теряется и на реплике, разорванной страницей. .fdx: `<Text Style="Bold">`, `Italic`, `Underline`, `Bold+Italic` в обе стороны; Fountain: разметка `**жирный**`, `*курсив*`, `_подчёркнутый_` (сочетания — `***`, `_**…**_`) в обе стороны, знак `*` или `_` в тексте экранируется по правилу Fountain (`\*`, `\_`), подчёркивание пишется только вокруг целых слов; Word: жирный/курсив/подчёркнутый прогоны в обе стороны (абзац, целиком набранный одним стилем, при загрузке считается оформлением стиля, а не текста, и приходит чистым).
- **Разрыв страницы** (Формат → «Разрыв страницы перед элементом», **Ctrl+Shift+Enter**, как Insert → Page Break): элемент начинает новую страницу на экране, в пагинации, хронометраже и PDF; повтор команды снимает. Над элементом видна линия «разрыв страницы · стр. N». Пометка (`block.pageBreak`) путешествует с текстом, как двойной диалог. .fdx: `StartsNewPage="Yes"` в обе стороны; Fountain: `===` в обе стороны. У первого элемента серии разрыв ничего не делает. Разрыв внутри реплики (на второй реплике персонажа или на ремарке) оформляется как естественный: «(ДАЛЬШЕ)» внизу страницы и «ИМЯ (ПРОД.)» вверху следующей; разрыв сразу после имени или заголовка уносит имя (заголовок) на новую страницу вместе с текстом.
- **Перейти к странице или сцене…** (Правка, **Ctrl+G**, как Go To в Final Draft): номер страницы по текущей пагинации или номер сцены (с буквами при локе номеров, например `12A`); курсор встаёт в начало страницы или на заголовок сцены.
- **(ПРОД.) автоматически**, как «Automatic Character Continueds» в Final Draft: если персонаж говорит в той же сцене снова, а между его репликами было описание, после имени на экране, в PDF и в .fdx стоит «(ПРОД.)». Это не текст: его нельзя выделить или стереть, оно пересчитывается вместе с вёрсткой; имя в элементе остаётся чистым, подсказки и статистика видят персонажа как одного. Если «(ПРОД.)» уже набрано руками, второе не ставится; у двойного диалога — не ставится. Выключается галочкой в «Параметрах страницы…» (`rules.autoContd`, по умолчанию включено). В .fdx оно пишется в текст имени, как делает сам Final Draft; при загрузке .fdx такие «(ПРОД.)» снимаются, где Драфт поставит их сам (при выключенной галочке — остаются текстом).
- **Цвет сцены** (карточка сцены в навигаторе, список из восьми цветов Final Draft и «нет»): цветная полоска у сцены в навигаторе и у заголовка на странице; на бумагу не идёт. Хранится в `sceneMeta.color`, входит в Ctrl+Z и файл проекта; .fdx: `SceneProperties Color` в обе стороны (цвета Final Draft приводятся к ближайшему из восьми, белый и чёрный — «нет»).
- **Подсказки имён и объектов** (SmartType): вкладки «Персонажи» и «Объекты» показывают, сколько имён и объектов в подсказках и сколько из них нет в тексте; у такой карточки есть ссылка «Убрать из подсказок» (у персонажа уходит и карточка библии со связями), а кнопка «Перестроить по тексту» убирает всё лишнее сразу, перечислив, что уйдёт. Имена и объекты, которые есть в любой серии проекта (в репликах, заголовках или составе сцены), убрать нельзя — они возвращаются из текста.
- **Правка: Вырезать, Копировать, Вставить, Выделить всё** (**Ctrl+X / Ctrl+C / Ctrl+V / Ctrl+A**) — в меню Правка и в меню по правой кнопке на странице (там же — тип элемента подменю «Элемент» и «Комментарий…»). Вставка из меню читает буфер обмена через браузер; если браузер не даёт читать буфер, Драфт просит нажать Ctrl+V. Вырезанный и вставленный текст забирает пометки разбивки с собой, как по клавишам.

## Поиск и замена

Правка → «Найти и заменить…» (**Ctrl+F**, когда курсор в тексте сценария) или «Заменить…» (**Ctrl+H**) — как Edit → Find / Replace в Final Draft. Панель стоит справа над страницей и не закрывает текст: все совпадения подсвечены, текущее — ярче.

- Параметры: «С учётом регистра», «Слово целиком» (буквы кириллицы — часть слова, дефис — нет: «иван» не найдёт «Иванович», но найдёт «иван-царевич»), «Элементы» — все или один тип (Сцена, Описание, Персонаж…), «Где» — эта серия или все серии проекта. Заголовки, персонажи и переходы ищутся так, как напечатаны (заглавными). Заглушка «УДАЛЕНА» — не текст.
- «Далее» (Enter, F3) и «Назад» (Shift+Enter, Shift+F3) идут от курсора; после последнего совпадения поиск начинается сначала («поиск с начала»). По всему проекту «Далее» открывает следующую серию. Выделенный перед Ctrl+F фрагмент становится запросом; Esc закрывает панель и выделяет найденное в тексте.
- «Заменить» меняет текущее совпадение и переходит к следующему (без текущего — сначала находит). «Заменить все» в открытой серии — один шаг Ctrl+Z; другие серии проекта перед заменой получают снимок «перед заменой» в «Истории» (Ctrl+Z работает только в открытой; такие снимки, как и «перед переименованием», при прореживании не удаляются). Замена пишется как набрана.
- Переименование: если по всему проекту в элементе «Персонаж» заменяется имя персонажа целиком (или в элементе «Сцена» — объект из словаря), «Заменить все» переименовывает его так же, как кнопки «Исправить» в проверке написания: реплики во всех сериях и карточка персонажа (объекта) вместе; у персонажа — ещё и состав без реплик в карточках сцен (`extras`, без повторов) и связи в карте отношений (пара, ставшая двойной, объединяется, подписи обеих сохраняются). Панель предупреждает об этом.
- Вкладка, устаревшая из-за правки в другой, только ищет (поле замены и кнопки недоступны).

## Драфты (ревизии) и лок страниц

Механика ревизий Final Draft, но без цветов: студия называет производственные ревизии по номерам (Производство → «Драфты…»). Слова не пересекаются: «Драфт N» — производственная ревизия, «версия» — сохранённая с названием копия текста в «Истории», «автоснимок» — снимок, который История делает сама. Исходный текст — «Драфт 1». В режиме «Продюсер» начинают следующий драфт: «Драфт 2», «Драфт 3» и так далее. Законченный драфт при этом сохраняется под своим номером в списке драфтов серии. Каждый драфт хранит копию текста на момент начала (`ep.revisions[]`: уровень, дата, кто начал, база); текущий — в `ep.revLevel` (уровень 0 = «Драфт 1», уровень n = «Драфт n+1»). «Сохранить версию…» предлагает имя «Драфт 3, версия 1».

- Всё, что изменилось относительно предыдущего драфта (новый элемент, другой текст, другой тип, перенесённый текст — например, сцена, сдвинутая кнопками ↑/↓, — а также элемент сразу после удалённого текста), помечается звёздочкой «*» на правом поле. Пометки текущего драфта выделены, пометки прошлых драфтов серые. Элемент держит самый поздний драфт, в котором менялся. Пометки на экране включаются галочкой «Показывать пометки», в строке состояния виден текущий драфт.
- PDF: звёздочки на 7,6" (на A4 — внутри листа), на изменённых страницах шапка «Драфт 2 — 01.11.2026», номер драфта на титуле; цветных полос нет. Опция «Только изменённые страницы» печатает титул, страницы с пометками текущего драфта под их прежними номерами и A-страницы сразу за ними (на них уходит текст, вытесненный с залоченной страницы).
- Лок страниц: после него каждая страница начинается с того же элемента. Текст, который не помещается, уходит на A-страницы (12A, 12B), укоротившаяся страница остаётся короткой. Удаление в конце залоченной страницы помечается на ней самой, а не на следующей; страница, с которой удалён весь текст, входит в номер предыдущей («2-3», как в Final Draft), и та уходит в замену. «УДАЛЕНА» остаётся на странице, где была сцена, и помечена только она. Номера одинаковы на экране, в PDF и в .fdx (страница сцены). Хронометраж считается по тексту, а не по коротким страницам. Снятие лока предлагает написать причину (можно оставить пустой) и пишется в журнал (`ep.pageLockLog`).
- .fdx: `<Revisions>` с наборами «Драфт N» и `RevisionID` на изменённых абзацах (Final Draft требует цвет у набора, поэтому в файл пишутся цвета WGA; в самом Драфте их не видно). При загрузке .fdx пометки Final Draft становятся драфтами серии с номерами; начатая в Final Draft ревизия без единой пометки тоже сохраняется. Даты наборов .fdx не хранит: после загрузки у драфтов дата загрузки.
- Номер драфта и лок страниц путешествуют вместе с текстом: Ctrl+Z, драфты и история возвращают их в том состоянии, в каком был текст. Исключение — режим «Сценарист»: восстановленный в нём драфт или снимок истории возвращает только текст, лок номеров сцен (вместе с замороженными номерами), лок страниц и номер драфта остаются (менять их может продюсер). Если лок снимает восстановление, сделанное продюсером, это пишется в `ep.lockLog` / `ep.pageLockLog` и в журнал действий с причиной «восстановлен драфт …».

## Разбивка сценария

Как Tagger в Final Draft и разбивка в Movie Magic. Выделите в тексте то, что нужно для съёмки, и выберите категорию: Производство → «Пометить для разбивки…» (**Ctrl+Alt+T**) или кнопка «+ Пометить» во вкладке «Разбивка». Цифры 1–9 выбирают категорию, можно добавить примечание. Категории: Реквизит, Костюм, Грим, Транспорт, Массовка, Трюки, Животные, Спецэффекты, Звук/музыка, Оружие, Декорация, Персонаж-эпизод — у каждой свой цвет.

- Пометки хранятся в серии (`ep.tags`: id, элемент, цитата, категория, примечание) и привязаны к тексту так же, как комментарии: правка, разбиение и склейка элементов их не теряют, а повторённое в элементе слово сохраняет свою пометку и после правок перед ним. Пометка переходит только вместе со своим текстом и не дальше своей сцены: если слово удалено или переписано, она не перескакивает на то же слово в соседней сцене, а ждёт возвращения текста (Ctrl+Z, драфт, «Вернуть сцену») и видна во вкладке «Разбивка» как «Текст удалён». Вырезанный (Ctrl+X) и вставленный в другом месте текст забирает свои пометки с собой.
- Вид → «Разметка разбивки» подчёркивает помеченный текст цветом категории (по умолчанию выключено, страница остаётся чистой). Щелчок по пометке показывает её и кнопку «Убрать».
- Разбивка целиком — инструмент режима «Продюсер»: у сценариста скрыты пункт меню, вкладка и «Разметка разбивки», **Ctrl+Alt+T** ничего не делает, а пометки, оставшиеся от сеанса продюсера, на его странице не подсвечиваются (сами пометки в серии остаются).
- Карточка сцены показывает её разбивку; вкладка «Разбивка» справа — всю серию по категориям с номерами сцен (щелчок — переход к сцене) и сводку по объектам.
- Трюки и животные из разбивки делают сцену особой для параметров студии (выработка ÷2,5); других источников у них нет: в карточке сцены есть только метки «Дети» и «Флешбэк». Старые карточки с другими метками (клип, массовка, грим…) читаются, метки просто не действуют; метки «Животные» и «Трюки» из старого проекта при первом открытии (из браузера или из файла проекта) становятся пометками разбивки на заголовке сцены с примечанием «метка сцены из старого проекта», и сцена остаётся особой — об этом говорит всплывающее сообщение. В списке сцен метка из разбивки обведена пунктиром.
- Экспорт «Разбивка в Excel (.xlsx)» (Файл → Экспорт и вкладка «Разбивка»): листы «Сцены» (номер, заголовок, объект, режим, ИНТ/НАТ/ПАВ, сценарный день, страницы в восьмых, хронометраж, персонажи, массовка и столбец на каждую категорию), «Объекты», «Персонажи», «Разбивка» и «По объектам» (что нужно на каждом объекте по категориям, как сводка во вкладке). Длина сцены в восьмых: живая сцена не короче 1/8 (как в Final Draft и Movie Magic) — в списке сцен, сайдах, Excel и .fdx.
- Пометки входят в Ctrl+Z, драфты и историю; при открытии файла проекта пометки обеих копий объединяются, убранные с любой стороны не возвращаются.

## Сайды

Сцены съёмочного дня для актёров и группы, как «Print selected scenes» в Final Draft (Производство → «Сайды…»).

- Отметьте сцены в списке (номер, заголовок, страницы) или быстрым выбором: «Сцены персонажа» отмечает все сцены, где он говорит или упомянут, «По сценарному дню» — сцены одного дня. Впишите получателей по одному в строке, срок (по умолчанию +3 дня) и пометку для шапки («Съёмочный день 12»).
- На каждого получателя — свой PDF (или все экземпляры одним файлом). В нём только отмеченные сцены по порядку сценария, в формате Final Draft, с номерами сцен с обеих сторон и пометками ревизий; невыбранные сцены пропущены целиком, титула нет. На каждой странице: шапка «Сайды · пометка · стр. N» (на странице с изменениями под ней отдельной строкой — название ревизии), имя получателя по диагонали, колонтитул «Экземпляр: имя · действительно до дата» и гриф коммерческой тайны (обладатель из «Титульного листа»; если он не задан — общий гриф «Коммерческая тайна» без имени). Тот же гриф всегда есть и в обычном PDF.
- Срок не может быть в прошлом. Каждый выданный экземпляр пишется в журнал проекта (`project.sidesLog`: кто выдал, режим, кому, серия, номера сцен, пометка, срок); экземпляр, файл которого не сохранён (сохранение отменено или не удалось), в журнал не попадает. Журнал виден в том же окне, истёкшие отмечены. Журнал входит в файл проекта и при открытии файла объединяется с локальным.
- Окно «Сайды…» (с выдачей и журналом) открывается в режиме «Продюсер»; сценаристу оно не показывается, как и всё меню Производство.
- Срок лишь напечатан на экземпляре: PDF не перестанет открываться сам. Журнал фиксирует выдачу, а не просмотр или пересылку.

## Сохранность и работа в команде

- **История (откат по времени)** хранит все снимки: автоснимок каждые 15 минут работы, при переключении серии и перед крупными изменениями. Снимки записываются как разница с соседним, более новым (последний — целиком, и каждый 30-й тоже, чтобы откат не шёл по длинной цепочке), поэтому месяц работы занимает немного места. Прореживание только по нехватке места: если история серии выходит за бюджет (40 млн знаков) или браузер сообщает, что хранилище заполнено больше чем на 90% или отказал в записи, сначала удаляются старые автоснимки (один в час старше суток, один в день старше недели, потом самые старые), и Драфт об этом предупреждает — всплывающим сообщением и строкой в окне «История». Снимки «перед …» (перед откатом, загрузкой файла, снятием лока…) не удаляются никогда; если состояние уже было снято обычным снимком, этот снимок получает пометку. Снимки старого формата (целиком) читаются и восстанавливаются как раньше. Перед записью снимка вкладка перечитывает историю серии из браузера (а приняв данные другой вкладки, сбрасывает свою копию), поэтому снимки, сделанные в другой вкладке, не затираются.
- Окно «История» (Файл → «История…») одно: автоснимки и сохранённые версии в одном списке по времени, со столбцом типа («Автоснимок» / «Версия»); у версии видны название, заметка и автор. Данные хранятся как раньше: версии в `ep.drafts`, автоснимки в `hist:<id>`. Кнопка «Сохранить версию…» есть в самом окне и в меню Файл (**Ctrl+Shift+S**). Из любой записи можно вернуть всю серию («Вернуть всю серию») или одну сцену («Вернуть только эту сцену»: сцена заменяется версией из записи, удалённая встаёт на своё место); разница с текущим текстом показана тут же. Перед откатом текущий текст сохраняется в истории снимком «перед …», откат отменяется Ctrl+Z и пишется в журнал действий. Отдельного окна версий нет, в навигаторе их списка тоже.
- **Журнал действий** (Производство → «Журнал действий…», режим «Продюсер»): общий для проекта и только пополняемый (`project.auditLog`) — снятие лока номеров и страниц (с причиной, если её написали), удаление и возврат серий и проектов из корзины, лок, снятый восстановлением драфта или снимка или загрузкой файла, откаты по истории, выданные сайды, начало нового драфта. Сюда же попадают записи `ep.lockLog` и `ep.pageLockLog` из старых проектов. Фильтры по серии и по действию. Удаление и возврат проектов пишутся ещё и в общий журнал браузера, чтобы след остался, пока проект в корзине. При открытии файла проекта журналы объединяются (каждая запись один раз).

## Параметры студии, персонажи, обмен

- Проверка по параметрам студии (вкладка «Параметры») — правила из документа студии: объём серии, сцен на страницу, дробность, основной павильон (% материала и смен), число объектов, новый объект не меньше N страниц, ночь вне павильона, натура, ночная натура, сцены больше 5 артистов, дети/животные/трюки, персонажей в серии; к ним — ручной список `MANUAL_CHECKS` (удалённость локаций, свет, бэкап-локации, массовые и музыкальные сцены) с галочками. Пороги — в «Параметрах студии». Мягких правил (баланс сцен на 2–3 артистов, сбор ансамбля, клипы, музыка, грим, «дорогие» артисты) нет; у персонажа в карточке остаётся только «несовершеннолетний» (он делает сцену особой).
- Линии (сюжетные линии или съёмочные группы): в «Параметрах студии» — названия и целевая доля материала каждой (`project.lines`), линия сцены задаётся вручную в её карточке (Навигатор → Сцены, `sceneMeta.line`) и видна в списке сцен. Вкладка «Время» показывает долю каждой линии, правило «Баланс линий» сравнивает её с целью (допуск `rules.lineTolerance`). Автоматического распределения сцен по линиям нет; у старого проекта с правилами автоматических линий (`lineRules`, объекты и персонажи линий) при первом открытии линия, которую сцена получала по правилам, записывается в её карточку, а правила убираются — об этом говорит всплывающее сообщение.
- «Word для FilmToolz (.docx)» (Файл → Экспорт; у окна одно имя и одно место в меню) открывает окно с проверкой перед выгрузкой: заголовки, в которых FilmToolz не распознает объект («СОН»), и расхождения в написании объектов и персонажей (регистр, пробелы, латинские буквы); та же проверка — во вкладке «Объекты», там её можно исправить кнопками.
- «Основной павильон» — объект, отмеченный основным, или павильон. Если нет ни того, ни другого (серия целиком на натуре), правило не засчитывает чужой объект, а показывает «Основной павильон не найден: 0% материала».
- «Натура» — доля хронометража сцен НАТ. и ИНТ./НАТ. вне павильона (`rules.extMaxPct`, по умолчанию 30%), «Персонажей в серии» — сколько разных персонажей в серии, с репликами и из карточек сцен (`rules.maxCharsPerEpisode`, по умолчанию 20). Оба поля — в «Параметрах студии»; 0 выключает проверку. Старые проекты получают значения по умолчанию.
- Библия персонажей: у каждой карточки номера сцен по сериям (щелчок открывает серию и сцену) и строка «связь с… / кто друг другу» — связь можно подписать для любого персонажа, не только из карты связей. Экспорт библии перечисляет сцены по сериям.
- Комментарии: «Решено»/«Открыть» запоминают, кто и когда (`resolvedBy`, `resolvedAt`). При открытии файла проекта и при возврате несохранённого из другой вкладки побеждает более позднее действие; в старых файлах без отметки времени комментарий решён, если решён в любой из копий.
- Титульный лист .fdx (`<TitlePage>`): Драфт пишет название проекта, «Серия N. Название», автора, справа — номер драфта («Драфт 2») и дату его начала (у «Драфта 1» — дату выгрузки), слева — контакты из «Титульного листа». При загрузке .fdx новая серия берёт название и номер (если он свободен в сезоне) из строки «Серия N. …», а без неё — название сценария; пустые «Автор» и «Контакты» проекта заполняются. Сам титул Final Draft хранится в серии (`ep.titlePage`) абзац за абзацем — выравнивание, шрифт, пустые строки, «Written by», строки, которых в Драфте нет, — и при выгрузке пишется обратно как был. Поле, изменённое в Драфте после загрузки (название проекта, серии, автор, контакты, новый драфт), заменяет текст своего абзаца. Титул путешествует с текстом: Ctrl+Z, драфты, история, файл проекта. Не сохраняются только элементы титула, кроме абзацев (например, `<HeaderAndFooter>`).
- Fountain (Файл → Экспорт → «Fountain (.fountain)»): файл `.fountain`; титул `Title`, `Episode`, `Author`, `Draft`, `Draft date`, `Contact` (несколько строк — с отступом), прочие ключи загруженного файла (`Credit`, `Source`, `Notes`…) пишутся обратно. Описание, которое Fountain прочитал бы иначе (как заголовок «Инт. кухня…», имя, переход, «МАША: текст», список «Маша, Петя» под заголовком, строка с `.`, `@`, `>`, `=`, `#`, `~`, `!`), выгружается с `!` и возвращается описанием. Реплика, которая начинается с разметки Fountain (`#`, `=`, `===`, `[[`, `/*`, `.`, `!`, заголовок «ИНТ. …», «ИМЯ. текст»), и `[[` / `/*` внутри любого текста выгружаются с невидимым пробелом нулевой ширины (U+200B): другие программы показывают текст как есть, Драфт читает его обратно без потерь. Кадр, который не похож на «строку заглавными» (длиннее 60 знаков, «(ДЕТАЛЬ)», «...И ТИШИНА», «…В:», «СМЕНА КАДРА»), пишется между двумя такими пробелами и возвращается кадром. Синопсис сцены — строка `= …` под заголовком, в обе стороны. При загрузке заметки `[[…]]`, «кладбище» `/* … */`, разделы `#` и разрывы страниц `===` убираются из текста; заметка на отдельной строке внутри реплики её не разрывает. Файл `.fountain` разбирается как Fountain и без титула.
- .fdx: тело удалённой сцены пишется в `<OmittedScene>` и при загрузке возвращается в карточку сцены («Вернуть сцену» его восстанавливает); синопсис сцены — это `<Summary>` внутри `SceneProperties` (Final Draft 10+), при выгрузке пишется и туда, и в `Title`, при загрузке без `Summary` берётся `Title`; абзацы внутри свойств сцены (Summary, SceneArcBeats) в текст не попадают, а заголовок сцены с ними не теряется; двойной диалог внутри удалённой сцены сохраняется в обе стороны; «Cast List» и другие нестандартные элементы распознаются по названию, как стили Word.
- **КИТ Сценарист (.kitsp) и Story Architect (.starc).** Файл → «Открыть…» (и перетаскивание) принимает файлы проектов обеих программ как есть, без выгрузки в .fdx; дальше — та же обработка, что у .fdx и Word: справочники персонажей и объектов, нумерация, отчёт о загрузке. Оба файла — базы SQLite, их читает sql.js (загружается при первом таком файле).
  - КИТ: текст — XML из таблицы `scenario` (строка `is_draft = 0`; если она пуста — «черновик»). «Время и место» → заголовок сцены (фиксированный номер `number` → номер сцены), «Участники сцены» → состав сцены (без реплик — в карточку сцены), «Описание действия», «Персонаж», «Ремарка», «Реплика», «Переход» → свои элементы, «Примечание» и «Лирика» → описание и реплика, «Заголовок титра» + «Титр» → одна строка описания «ТИТР: …», «Описание сцены» → синопсис сцены, двойной диалог (`splitter_start` … `splitter` … `splitter_end`) → пара реплик. Папки и «Непечатаемый текст» в текст не попадают. Название, автор и контакты из `scenario_data` (`name`, `author`, `contacts`) — титульный лист серии, как при загрузке .fdx.
  - Story Architect: текст сценария — документ типа 10104 (`ScreenplayText`) в таблице `documents`; его имя — название сценария из документа структуры (тип 1), оно становится названием серии. Сценарии из корзины и сохранённые версии (`<draft>`) не берутся; если в проекте несколько сценариев или серий, Драфт спрашивает, какой загрузить (по одному за раз). У сцены: номер, если он зафиксирован или задан вручную, сценарный день (`story_day`, берётся число), описание → синопсис, «удалённая» сцена (`omited`) → УДАЛЕНА с телом в карточке; «Кадр» → кадр, «Лирика» → реплика, «Неформатированный текст» → описание; заметки, биты, акты и последовательности в текст не попадают; двойной диалог — по `splitter` и признаку колонки `params ifc`.
  - Что не подтверждено на настоящих файлах: формат восстановлен по открытому исходному коду обеих программ (KITScenaristCore, story-apps/starc), тесты используют синтетические базы (`tests/kitstarc_fixtures.js`). Не проверены: старые файлы КИТ без `version="1.0"` (читаются тем же разбором, неизвестные элементы пропускаются), точная запись `splitter` в STARC (поддержаны `type="start"/"end"` и вариант КИТ), сжатое содержимое документов STARC (в исходниках сжатия нет; такой документ будет пропущен). Пометки рецензирования, форматирование (жирный, курсив), закладки, цвета и драфты/версии обеих программ не переносятся.
- Word для FilmToolz: заголовок без распознанного объекта («СОН») сохраняет свой текст, строка заголовка всегда заканчивается точкой.
- Автодополнение объектов и подобъектов: объект, набранный полностью, стоит в списке первым, поэтому Enter и Tab не превращают «КУХНЯ» в «КУХНЯ ЛЕНЫ».
